# AwaazGuard: Audio Deepfake & Voice-Clone Scam Detection

AwaazGuard checks whether a voice note or call recording was spoken by a real person or generated by
an AI voice clone, and shows **which seconds** look machine-made. It is a complete MLOps system:
reproducible training, a model registry, cloud deployment with Docker, canary releases, drift
monitoring, a continuous red-team release gate and automated retraining. **Every tool and service
used is free**, and nothing requires a credit card.

**Start with `docs/FINAL_DELIVERABLE_STEP_BY_STEP.md`** (the step-by-step plan for the final deliverable,
with the commit split between both team members). `docs/AwaazGuard_Handbook.pdf` has the long
explanations of every tool; where the two differ, the step-by-step file is newer.


| Layer | Tools (all free) |
|---|---|
| Data + pipeline | DVC (`dvc.yaml`, 9 stages), DagsHub storage |
| Models | LFCC-GMM baseline, AASIST-L main (PyTorch) → ONNX Runtime for serving |
| Tracking + registry | MLflow on DagsHub (Staging = candidate, Production = champion) |
| Serving | One FastAPI app: website + gateway + both ONNX models in-process (HTTP backend available for scaling) |
| Frontend | Next.js static export (upload / record, waveform + spectrogram + per-second risk, ops dashboard) |
| Storage | SQLite + local volume |
| Monitoring | Prometheus + Grafana, Evidently drift reports, Docker logs |
| Red-team | Piper TTS / XTTS-v2 voice cloning + phone/Opus/MP3/noise channels |
| Orchestration | Prefect (retrain flow, canary flow) |
| Cloud + IaC | **Azure for Students** (no credit card) free VM, provisioned with Terraform |
| CI/CD | GitHub Actions + GitHub Container Registry (free for public repos). **Eval-gated:** every pull request runs unit tests, data validation and a champion-vs-challenger model gate; CD deploys only after CI is green |

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env                                     # DagsHub MLflow credentials
python scripts/init_feedback.py && dvc add data/feedback
dvc repro                                                # download, validate, train, export, register
python -m scripts.promote --version 1 --stage Production # first champion
cp deploy.env.example deploy.env                         # secrets for the stack
docker compose --env-file deploy.env up -d --build       # http://localhost
```

Every step is explained, with screenshots of what to expect and fixes for common errors, in the
**handbook**.

## CI gates (every pull request)

| Job | What it does | Blocks when |
|---|---|---|
| `unit-tests` | Lint + all tests (serving, gateway, drift, canary, data-validation and gate logic) | any test fails |
| `data-validation` | `scripts/validate_processed.py` on the DVC-versioned dataset: schema, nulls, duplicates, label and attack ranges, missing files, sample rate, duration, silence, clipping, speaker-disjoint splits | corrupted, missing or leaky data |
| `model-gate` | `scripts/model_gate.py`: scores the Production champion and the Staging challenger through the real serving code on a **fixed** test set (seeded sample of the unseen-attack eval split) | challenger EER is worse than the champion by more than `gate.tolerance`, or the champion is above `gate.max_eer` |

Settings are in `params.yaml` under `gate:`. `cd.yml` runs only after the CI workflow succeeds on
`main`, so a failed gate blocks deployment. Turn the three jobs into required checks (Settings →
Branches) to also block the merge button.
